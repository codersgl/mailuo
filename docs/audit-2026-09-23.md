## A 安全

### A1（高）API 监听所有网卡，Tailscale 与同网段主机可无鉴权读写全部数据

具体追踪（我实测）：`apps/api/src/index.ts:18` 只传了 `port`，`@hono/node-server` 最终执行 `server.listen(port, undefined, cb)`，Node 对 `undefined` 主机名绑定 `::`（本机 `/proc/sys/net/ipv6/bindv6only = 0`，IPv4 一并接收）。此刻用户自己的 dev server 就在跑，实测：

```
ss -ltn | grep 3003        ->  LISTEN 0 511  *:3003  *:*
curl -s -o /dev/null -w '%{http_code}' http://10.32.213.214:3003/api/health  ->  200
curl -s -o /dev/null -w '%{http_code}' http://100.65.77.53:3003/api/health   ->  200
```

而 `GET /api/tree` 一次返回全库任务，写接口可新建、改、归档、删除整棵子树，全程无凭据。启动日志却印的是「API 监听 http://localhost:3003」（`index.ts:19`），与真实绑定不符。`docs/` 里没有任何关于 bind 地址的记录。

为什么这是缺陷而不是「单用户应用的正常状态」：`docs/spec.md` 排除的是账号系统，不是网络暴露面。规范把应用定位为「个人使用」，默认语义是只服务本机；现在任何 tailnet 设备（`tailscale status` 里有 windows / android 两台）或 10.32.0.0/16 上的主机都能改这份数据。若用户确实想把看板开到手机上用，那是一个产品决定，需要记录并补一层凭据，而不是靠默认值悄悄发生。

建议（二选一，需要用户拍板）：
1. 默认只服务本机：`serve({ …, hostname: '127.0.0.1' })`，另加一个 `HOST` 环境变量用于显式放开；日志改成打印 `info.address`。
2. 保留跨设备访问：加一个共享 token（请求头或子路径前缀），并在 `docs/decisions.md` 记录「局域网/Tailscale 可用」这一决定。

### A2（高）没有 Origin / Host 校验，DNS rebinding 可让任意网页拿到同源读写

证据：`apps/api/src` 内 grep `origin|trustedHost|allowedHost` 无命中；唯一与跨站有关的防线是写接口的 Content-Type 检查（`apps/api/src/routes/tasks.ts:39-49`），而它只挡表单类跨站请求。`@hono/node-server` 只校验 Host 与 URL 自洽，不比对白名单。

我实测（自建实例，端口 3112）：

```
curl -H 'Host: evil.example' http://127.0.0.1:3112/api/health                     -> 200
curl -H 'Host: evil.example' -H 'Origin: http://evil.example' …/api/health        -> 200（响应无 CORS 头）
```

触发链：用户打开恶意站点 → 该域名先解析到攻击者、再重绑定到 `127.0.0.1` → 浏览器认定页面与 API 同源 → 同源 `fetch` 可自由带 `Content-Type: application/json`，既不触发预检也不受「没有 CORS 头」的限制 → 读 `/api/tree` 并任意写。

注意：这一条与 A1 是两件事。即使把 bind 收回 `127.0.0.1`，DNS rebinding 依然成立，缺的是 Host/Origin 白名单。建议加一个最小中间件：Host 只认 `127.0.0.1:<port>` / `localhost:<port>`（以及用户在 A1 里决定开放的地址），非 GET 请求再要求 `Origin` 缺失或同源。开发态不受影响——`apps/web/vite.config.ts` 的代理设了 `changeOrigin: true`。

### A3（中）没有请求体大小上限，单个超大请求能把 Node 进程打爆

`grep -rn bodyLimit apps/` 无命中（Hono 的 `bodyLimit` 是 opt-in 中间件）。zValidator 走 `c.req.json()`，整块读进内存再 parse；`@hono/node-server` 只丢弃「未被读取」的 body，不设容量上限。一条 `POST /api/tasks` 带几百 MB 到几 GB 的 JSON、或 chunked 慢速发送，就能让个人服务器上的进程 OOM。修法是注册 `bodyLimit({ maxSize: 256 * 1024 })`（描述上限 10000 字，256KB 足够），或按 `Content-Length` 提前回 413。

### A4（低）SQLite 主库与 WAL/SHM 文件是 0644

实测 `data/kanban.db`、`-wal`、`-shm` 都是 `-rw-r--r--`（目录 0755）。同一台多用户机器上的其他本地用户可以直接读走全部任务，`-wal` 里可能还有未 checkpoint 的写入。修法：`openDatabase` 建库后 `fs.chmodSync(dbPath, 0o600)` 并让 WAL/SHM 跟随（进程 umask 077），或在 README 里写明「仓库放在 0700 目录下」。个人单用户机器上优先级低。

### A5（低）没有速率限制

无任何限速中间件；`GET /api/search` 的 `LIKE '%…%'` 是前导通配符，每次都是全表扫描。配合 A1 的无鉴权，局域网主机可以一直刷。修法上不必单独做限速——把 A1 的 bind 收回本机就基本消除；若用户选择跨设备访问，再考虑令牌与限速。

### A6（低）超大子树归档 / 删除会撞 SQLite 变量上限，500 之后无法再操作

`apps/api/src/repositories/tasks.ts:512-517` 与 `:570-576` 把子树 id 展开成占位符；删除路径 `...ids, ...ids` 用两遍。我实测 SQLite 3.53.4 的上限：

```
1000 个占位符 ok；32766 个 ok；32767 个 -> too many SQL variables
```

即归档超过约 3.2 万个节点、删除超过约 1.6 万个节点会抛错 → 500，且这棵子树此后既不能归档也不能删除（只能手改库）。个人规模下不会碰到，属构造性场景；真要修就把 `IN (…)` 换成内联 `IN (SELECT id FROM subtree)` 或分批执行。

### B1（高）生产静态托管没实现，而规范已经承诺

规范 `docs/spec.md:80`：「生产：Hono 提供 `/api/*`，并用 `serveStatic` 托管 `apps/web/dist`，只跑一个进程。」实测 `grep -rn serveStatic apps/` 只命中文档，`apps/api/src/index.ts` 只挂 API。`pnpm build` 之后跑 `node apps/api/dist/index.js`，`GET /` 得到 `{"error":"not found"}`，`/board/:taskId` 刷新也没有 SPA fallback。`docs/decisions.md:282/322/790` 自己记过「还没实现」。**改代码**：加静态托管 + 非 `/api` 路径回落 `index.html`。它还有一个安全副作用——用户为了能用，很可能拿 `vite --host` 把开发服务器开到网上，那会连带暴露源码与 sourcemap。

### B2（中）搜索结果到底带不带工期字段，规范内部打架

### B3（中）依赖图的 Esc 取消选中只在节点仍持有焦点时生效

规范 `:322`：「点节点是选中……点空白处或按 Esc 取消选中。」实现里 Escape 只挂在节点按钮的 `onKeyDown`（`apps/web/src/components/DependencyGraph.tsx:423-427`），舞台和 document 上都没有监听。点过详情卡、或浏览器（Safari）点按钮不赋焦点时，按 Esc 没有任何反应，只能点空白处。**改代码**：选中非空时在舞台（或 document）上接一个 Escape。

## C 前端健壮性

安全性结论：没有发现 XSS 或注入类问题（`src/` 下无 `dangerouslySetInnerHTML`/`innerHTML`/`eval`/`new Function`；标题、描述、摘要、路径、搜索词都只走 JSX 文本节点；`index.html` 的主题引导脚本只把 localStorage 里的值跟 `'light'`/`'dark'` 两个常量比较，不拼 DOM），URL 里的 taskId 全程当不透明 id 并逐个过 `encodeURIComponent`，localStorage 脏值一律回落默认值。问题集中在下面几类。

### C1（中）没有请求超时，后端不响应时界面永久停在「加载中…」且没有重试入口

`apps/web/src/api/client.ts:39-43` 的 `fetch` 没有 `signal`；`useAsync` 只有 reject 才会进 `failed`（`useAsync.ts:63-78`）。触发条件是「连上了但不回包」（后端卡死，或端口被另一个只接受连接不回包的进程占用——本机历史上真被占过，见根 `.env` 注释），此时 `fetch` 永不 settle：看板、任务树、面包屑、依赖图全部永久 loading，重试按钮永远不出现；写操作也永久 pending（「添加」一直显示保存中），只能刷新页面。**改代码**：`request` 里加 `signal: AbortSignal.timeout(10_000)`，把超时映射成 `ApiError(0, '后端响应超时，请重试')`。注意 `docs/decisions.md:225` 当时明确不做 AbortController（理由是拖拽竞态已有 cancelled 守卫），这次要处理的是另一件事——超时，不是取消。

### C2（中）成功响应不校验形状，且没有错误边界，异常会白屏

`client.ts:67` 只校验「是不是 JSON」就 `return body as T`；`main.tsx` 直接 `createRoot(...).render(...)`，全仓没有 `componentDidCatch`/`getDerivedStateFromError`。任何「200 + 合法 JSON 但不是契约形状」的响应（代理目标被别的进程接管、后端版本不一致、后端 bug 返回 `{}`）都会让 `board.columns.map` 之类的渲染期访问抛 TypeError，React 19 随即卸载整棵树——白屏且没有任何提示。**改代码**：最小改动是在 `main.tsx` 包一层 ErrorBoundary（「界面出错，请刷新」+ 重试按钮）。

### C3（中）拖拽、依赖图平移与 30 秒 tick 都会全量重渲染，大列表下会卡

- `useCardDrag.ts:95-100` 每个 `pointermove` 都对列内所有卡片做一次 `getBoundingClientRect`（强制同步布局），树拖 `lib/tree.ts:138` 每次重建后代集合（O(任务数)，n=500 时每帧约 1000 次 Map/数组操作）。
- `BoardView.tsx:53` 的 `useNow()` 每 30 秒重渲染全部卡片；`DependencyGraph.tsx:133` 每次平移/缩放都重渲染全部节点与边。
- 全仓没有一处 `React.memo`（已核实 grep 无命中）。

个人库规模（几十个任务）下不构成问题，但这是一条随数据量线性恶化的路。**改代码（可选）**：拖拽开始时缓存 rect、树拖在 `onStart` 缓存后代集合、`TaskCard`/`NodeCard` 用 `memo`。属于「将来卡了再改」的加固，不是当前缺陷。

### C4（低）插入线用未转义的列 id 拼 CSS 选择器

`BoardView.tsx:116-118` 的 `querySelector(`[data-column-id="${slot.columnId}"] [data-column-body]`)`。列 id 正常只有 `todo`/`doing`/`done`，只有手工改库造出含 `"` 的 id 才会让 `querySelector` 抛 `SyntaxError`；而因为没有 ErrorBoundary（C2），这一抛就是白屏。**改代码**：`CSS.escape(slot.columnId)`，或遍历 `[data-column-id]` 比较 `dataset.columnId`。

### C5（低）搜索态下从任务树或面包屑导航不清空关键词，结果页继续盖着主区

`App.tsx:271-274` 的 `openResult` 会清词，但传给 `TopBar`（`:360`）和 `Sidebar`（`:367`）的是裸 `onNavigate`，换 `boardId` 的 effect（`:146-150`）也不清 `keyword`。于是搜索时点任务树节点：URL、面包屑、树的选中态都变了，主区还是结果页，看起来「点了没反应」——正是 `openResult` 注释里要避免的那个症状。规范 `:307` 只规定了「从结果进入某个任务时清空搜索词」，没规定树/面包屑这条路径。**这是一个需要用户拍板的产品问题**：若认为「搜索时从树跳走也该回到看板」，改法是把传给 TopBar/Sidebar 的 `onNavigate` 包一层清词；若认为「搜索态下从树导航、结果页留着」是有意的，就把它写进规范。

### C6（低）折叠态徽标与展开态徽标口径不一致

`TreeNodeRow.tsx:151-153` 折叠时显示 `children.length`（含归档子任务），展开时显示 `countChildren(node)` 的 `done/total`（不含归档，`lib/tree.ts:61-70`）。打开「显示已归档」并折叠一个含归档子任务的节点，会看到「5」与「3/5」并存，像是数据变了。**改代码**：折叠态也用 `countChildren` 的结果，或者明确接受两种口径并统一文案。

### C7（低）渲染期写 ref

`App.tsx:157-158`（`boardRef.current = …`）、`App.tsx:234`、`useCardDrag.ts:125-126`、`useTreeDrag.ts:59-63` 都在渲染阶段给 ref 赋值。当前没有可观测故障（React 19 未启用并发渲染），但这是时序脆弱点：将来启用 `startTransition` 之类特性时，被丢弃的那次渲染会把 ref 写成废弃分支的值。**改代码（可选）**：移到 `useEffect`，或用 React 19 的 `useEffectEvent`。`docs/decisions.md` 里已有「渲染期写 ref 幂等、可接受」的判断，所以这条只是备案。

## G 检查过、确认不构成缺陷的点

记在这里是为了避免以后重复怀疑同一批地方。

- **SQL 注入**：`apps/api/src` 里 20 处 `db.prepare/exec` 全参数化，模板串插值的只有代码常量（`TASK_COLUMNS`、`SUBTREE_IDS_CTE`）与按数组长度生成的 `?` 占位符；`conditions.join(' AND ')`/`assignments.join(', ')` 的片段也都是常量；迁移文件名用 `?` 绑定，且文件来自固定目录、被 `/^(\d+)_/` 约束。没有一处把用户输入拼进 SQL。
- **XSS / 渲染注入**：前端没有 `dangerouslySetInnerHTML`/`innerHTML`/`eval`/`new Function`/`document.write`；任务标题、描述、搜索摘要、面包屑、URL 里的坏路径全部只走 JSX 文本节点或属性值。后端存原始文本不清洗是可接受的。
- **错误信息泄露**：非 `HTTPException` 一律回 `{error:'internal server error'}`，堆栈只进 `console.error`；`{error}` 里回显的只有调用方自己传的 id。
- **入参上限**：title ≤200、description ≤10000、durationMinutes `.int()` + `.max(4799520)`、q ≤100；`position` 虽无上界但被 `Math.min(position, siblings.length)` 夹住；`spentMinutes`/`runningSince` 无法通过任何入参写入。
- **CSRF**：写接口强制 `Content-Type: application/json`，跨站表单构造不出该头；DELETE/PUT 属非简单方法，没有 CORS 头时预检即失败。开发态走 Vite 同源代理。（这一层会被 A2 的 DNS rebinding 绕过，所以 A2 仍要修。）
- **CORS 默认拒绝**：没有任何 CORS 响应头是默认安全，不是缺陷。Vite 7 的开发服务器默认只允许 `localhost`/`127.0.0.1` 的 Origin，也无需处理。
- **PRAGMA 与事务**：唯一的连接入口 `openDatabase` 每个连接都设 `journal_mode = WAL` 与 `foreign_keys = ON`；五个写入口都用 `.immediate()` 事务规避锁升级；`busy_timeout` 取 better-sqlite3 默认的 5000ms。
- **localStorage 与 URL 脏值**：`readStored` 对非 JSON、形状不符、Storage 抛异常一律回落默认值；路由只认 `/` 与 `/board/:id`，非法百分号编码进 NotFound，taskId 全程当不透明 id 并过 `encodeURIComponent`。
- **数值健壮性**：超长数字在 `lib/format.ts` 被 `Number.isFinite` 挡住，不会出现 `Infinity → JSON null` 静默改数据；`progressPercent` 对 0 子任务返回 0，不会 0/0。
- **请求竞态**：`useAsync` 用每轮 effect 独立的 `cancelled` 丢弃晚到响应，`useSearch` 在关键词/开关变化时 `clearTimeout` + cancel；测试用「后发先回」钉住。
- **计时不变式**：五个会改列或归档状态的写入口都调了 `settleClock`/`settleSubtreeClocks`；对真实库副本与迁移重建的空库实测违规计数都是 0。
- **CPM 正确性**：与规范 164-172 条条对应，另有独立公式在随机 DAG 上交叉验证（D42 记录）。
- **「明确排除」的东西没有偷偷实现**：grep `dueDate`/`deadline`/标签/附件/WebSocket/通知/Service Worker 全部 0 命中；列由后端固定，无自定义列入口；卡片拖拽不会跨层改父级。
- **前端性能的一个误报**：`vite.config.ts` 的代理只监听本机、`changeOrigin` 对 127.0.0.1 无副作用，生产构建不受 `server.*` 影响。
- **文本与命名**：`apps/` 下已无「文件树」这一旧名（只剩一条测试注释在解释变异检验）。
- **契约表可信**：`docs/spec.md` 的 13 条路径与 `apps/api/src/routes/*.ts` 的真实路由一一对应、拼写一致，`/api/board/cpm` 也正确地注册在 `/api/board/:parentId` 之前；多出来的只有未记录的 `/api/health`（B9）。
- **README 与脚本一致**：README 列的 6 个 `pnpm` 命令与根 `package.json` 的 scripts 完全对应，`PORT`/`KANBAN_DB_PATH` 的说明与 `config.ts`、`vite.config.ts` 的实现一致；缺的只是生产段落（B1）。
- **无遗留物**：`apps/` 下没有 `TODO`/`FIXME`/`HACK`/`eslint-disable`，`console.*` 只出现在启动信息与 `app.ts` 的错误日志；`dist/` 未入库。
- **测试纪律**：全仓无 `skip`/`only`/`todo`、无被注释掉的用例；`useCardDrag` 的点击/拖拽分界用真实 `Date.now()` 语义加真实任务边界，避免微任务假通过（这一点曾经真的被审阅抓到过）。
